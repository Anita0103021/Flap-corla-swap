# 限次竞争狙击与测速记录 · 2026-11-12

## 使用

1. 网页「开盘狙击」加入尚未开盘的 Corla v4 项目，设置钱包数、金额、当前报价滑点和每项目每钱包的最多提交数。另有独立的「开盘价溢价上限」，默认 10%，可收紧至 0%。设成 1 为确认后单次；开启「没抢到开盘就不追」需设为 2–5，不会自动提高次数。
2. 核对预算再启动。按每次都要承担本金与 Gas 的保守上限计算；实际链上回退也可能耗 Gas。下一次是同一最低到手量，不自动提高滑点或 Gas 上限。
3. 每次实盘狙击启动后，状态栏显示 `reports/snipe-runs/snipe-*.ndjson`。结束后可从项目目录取这一个文件进行比较。异常退出可能只保留已写入部分。不要发送 `config.local.json`、钱包库或整个 `state/`。

## 路径与边界

- 待打包订阅使用 PublicNode 的完整交易流；可用 `BSC_PENDING_WSS_URL` 指定其他支持完整 pending 对象的 BSC 节点。不展开 hash-only 消息，也不对整个 mempool 逐哈希查询。已验证末笔须匹配签名、链 ID、目标合约、父块上的 nonce、金额及 Corla 工厂/合约身份。
- 提前路径只在可还原「最后一笔 Mint → 我方买入 → 模拟授权 → 模拟卖出」顺序且验证真实池、注资、税和最低到手量时放行。买入可以在链上开盘前提交，授权/卖出仅模拟。父块过旧、重组、模拟失败、目标不公开等条件都可能错过提前发单。默认允许受硬价格上限约束的确认后买入；开启「没抢到开盘就不追」时，确认后不补位，识别到开盘后不再新签，但不会撤销已广播的交易。

- 两条路径都把当前报价滑点与开盘价溢价换算为最低到手量，并取两者较高值。确认后路径不能用开盘区块结束时的储备替代交易内的初始注资；已有其他买家进场时，低于开盘保护底线的报价直接跳过。
- 每次最多发一条 raw 到一个节点；不会叠加未决 nonce、替换或公开回退到多个节点。上笔已验证回退或明确拒收才可继续。SQLite 持久化次数、金额、代币及原始最低到手量，防止重启提高次数或降价追单。
- 不使用 Builder、小费或私有排序；公开待打包流与 RPC 可能漏报或延迟。提前模拟有耗时且可能错过有效窗口，不能保证同块或首笔成交。

## 对比看哪些字段

- `snipe_pending_match`：同一开盘哈希是否先从待打包流收到；`leadMs` 只相对本机开盘通知。
- `snipe_send` / `snipe_ack`：准备提交和节点应答；应答不等于成交。
- `snipe_race_outcome` / `snipe_receipt`：尝试序号、已知结果、回执区块和块内索引；若仍未知，不能算作成交。
- `snipe_first_buy`：延迟查询从开盘块至后续最多两块观察到的首买。比较「成交块 − 开盘块」，若同块再比较块内索引。停止太早或节点查询失败时可能缺少这条补充记录。
- `buy_skipped` 的 `failureKind: opening_price_cap`：价格保护拒绝。`openingNetOut`、`quotedNetOut` 和 `openingAmountOutMin` 分别为开盘净报价、当前净报价和开盘保护下限（代币最小单位）。

日志不保存钱包地址、RPC 凭据、会话、私钥或原始交易。公开交易哈希可在浏览器追溯链上交易发起者。
