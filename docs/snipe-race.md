# 限次竞争狙击与测速记录 · 2026-11-12

## 使用

1. 网页「开盘狙击」加入尚未开盘的 Corla v4 项目，设置钱包数、金额、当前报价滑点、并发线程数和并发次数。并发线程数为每轮同一笔签名买单的 RPC 投递上限（1–8，默认 1）；并发次数为每项目每钱包的尝试上限（最多 20 轮）。默认勾选「没抢到开盘就不追」，配 2 轮；关闭后可选 1 轮（确认后单轮）。另有独立的开盘价溢价上限，默认 10%，可收紧至 0%。
2. 核对预算再启动。BNB 项使用全局 BNB 金额；USDT 等 ERC-20 项在各项目中填写该支付币的买入额和最低池储备。ERC-20 本金和 BNB Gas 分开；钱包的 Router 额度不够时，实盘确认后先做限额授权。实际链上回退仍可能耗 Gas。下一次沿用原买入额和最低到手量，不自动提高滑点或 Gas 上限。
3. 网页每次接受实盘狙击启动请求（配置和预算已通过检查）就新建一个 `reports/snipe-runs/snipe-*.ndjson`，包括之后启动失败、取消或没有成交的运行。记录边跑边写，正常停止后会补齐 `run_end` 汇总；异常退出可能只保留已写入的部分。状态栏显示最近一份文件的路径，重启后也可看到。不要发送 `config.local.json`、钱包库或整个 `state/`。

「并发次数」下方实时显示投递时间：1 轮的 RPC 投递超时为 2.2 秒（不含前置检查或链上确认）；2–20 轮共用从首轮尝试提交开始的 4.8 秒重试窗口，到期停止新投递，已在途的请求与回执核对另计。等待待打包 Mint 的时间既不计入 4.8 秒，也不消耗轮数。轮数是上限，不是固定的发送次数。

## 路径与边界

- 待打包订阅默认使用 PublicNode 的完整交易流。可用 `BSC_PENDING_WSS_URL` 指定主来源，并用 `BSC_PENDING_WSS_BACKUP_URLS` 添加最多两个支持完整 pending 对象的独立 WSS（逗号分隔，启动后台前设置）。来源并行监听，一路掉线或地址配置有误不影响其他路；按哈希保留最早到达的一份。
- **以真实数据判断连接。** 订阅后连续 8 秒没收到完整待打包交易会主动重连，只有哈希也一样，不展开查询整个交易池。瞬时故障按 0.5–8 秒退避持续重试；稳定恢复后回到短退避。链 ID 明确错误或者节点明确不支持订阅时，保留状态提示以便更换节点。「狙击状态 → 待打包 WSS」按路显示最近完整推送、以及是否重连；全路暂不可用时单独提醒，确认开盘的监听不受影响。有完整流不代表它覆盖每一笔交易。
- BNB 按目标合约的 `mint` 匹配；ERC-20 按已验证工厂的 `mintQuote` 和项目登记键匹配。每项目只保留最近 2.5 秒内最多 6 个候选。
- **最后 1–3 批可以同块完成。** 例如父块是 47/50，若收到 3 笔完整候选，核验其原签名、链 ID、各发件人在父块的 nonce、累计余额及 ERC-20 额度，再按 nonce 和到达顺序构造连续的 Mint 模拟。前两笔须分别把进度推到 48/50 和 49/50，第三笔须打满并开盘。项目和候选核验在各狙击钱包之间共享；短缺的候选或超过三批的缺口只记录等待，不发单。
- Corla 创建页采用 `dexId=0` 的 PancakeSwap V2 直连池，底池资产与 DEX 是两个独立字段。配置和开盘前预演按项目核验链上底池开放状态、实际精度和对应的 V2 路径，不使用看板里的候选名单作为交易白名单。已确认的开盘仍以回执中的官方建池和注资证据为准。
- 提前路径只在可还原「最后 1–3 笔 Mint → 我方买入 → 模拟授权 → 模拟卖出」顺序且验证真实池、注资、税和最低到手量时放行。买入可以在链上开盘前提交，授权/卖出仅模拟。父块过旧、重组、模拟失败、待打包交易未被节点看到等条件都可能错过提前发单。默认开启「没抢到开盘就不追」：收到匹配的开盘信号就暂停新的提前发单，已确认的开盘不再补买；已广播的交易仍可能成交。关闭后才允许受硬价格上限约束的确认后买入。

- 两条路径都把当前报价滑点与开盘价溢价换算为最低到手量，并取两者较高值。确认后路径不能用开盘区块结束时的储备替代交易内的初始注资；已有其他买家进场时，低于开盘保护底线的报价直接跳过。
- 每轮只签一笔，按并发线程数将同一份 raw 同时投给现有的健康狙击 RPC，每个节点最多一个请求。有效应答必须匹配本地哈希。上一轮已验证回退或所有投递均明确拒收时才可继续；超时、异常应答等不明结果仍按原哈希核对。SQLite 持久化次数、金额、代币及原始最低到手量，防止重启提高次数或降价追单。
- 不使用 Builder、小费或私有排序；公开待打包流与 RPC 可能漏报或延迟。提前模拟有耗时且可能错过有效窗口，不能保证同块或首笔成交。

## 对比看哪些字段

### 2026-11-18：候选有效性与诊断补强

- ABI 匹配的首帧不再直接占用执行去重名额。另一来源随后送来的同哈希完整签名允许升级，已核验候选保留不可变快照；不完整或伪签名帧不启动父块/顺序模拟。准备阶段的失败签名缓存也允许被同哈希的新对象修复。
- 模拟结束、签名前、投递前核对所选 Mint 是否已被已观察到的有效同 sender/nonce 交易替换或超过候选时限。头块未前进不增加 nonce RPC；头块前进才按选中 sender 并行核对最新 nonce，避免沿用已经消耗的 nonce。只覆盖实际观察到的有效替换，不能推断私有交易池；当前纯签名校验不覆盖 `to=null` 合约创建取消。
- 开盘通知计时沿用 feed 最初收包的 monotonic 时间，不在排队后重置起点。此项修正的是测量准确性，不是消除了真实网络延迟。
- 新增 `snipe_pending_source`：每源首见匹配对象与首次完整签名的到达。`signatureVerified` 区分残缺帧和可还原签名；不记录签名或原始交易。
- 新增 `snipe_pending_source_match`：按准确开盘哈希和来源记录已验签交易的有符号 `leadMs`（正=本机先见，负=迟到，`null`=未见有效签名）。确认后才收到的签名会补记迟到结果，不会触发新买入。流健康与这笔交易是否提前可用分开判断。
- `snipe_first_buy.amountIn` 为兼容旧日志仍指首条观察到的买入 Swap。只有补查到同一成功回执，核对区块哈希/交易索引并从 receipt.logs 汇总后，才设置 `firstBuyAggregationComplete=true`：`firstBuyTotalIn` 为同一交易、同一池所有买入腿的投入总额，`firstBuyQuoteOut` 为卖出腿的支付币返还，并提供买/卖腿次数。重复 logIndex 只计一次；缺少回执或 logIndex 不声称已得出完整合计。首买身份仍是指定区块范围内 RPC 观察到的最早买入，不据此保证上游没有漏掉更早的其他交易。

离线分析一份运行文件：

```powershell
node scripts/analyze-snipe-run.mjs '<单份 snipe-*.ndjson 的路径>'
```

分析器只投影公开哈希、数字和固定诊断码，不重新查链、不读钱包。旧日志没有逐源验签信息时给出 `null`/unknown，不冒充 0% 覆盖；按事件输出阶段 p50/p95，不能把并行阶段分位数相加作为端到端延迟。

- `snipe_pending`：完整待打包 Mint 进入本机 WS 消息回调时的时间，`time` 为 UTC（含毫秒），`pendingReceivedAtMs` 是同一时刻的 Unix 毫秒值，用 `pendingTxHash` 查找。`pendingSource` 是最早收到它的 WSS 编号，不保存节点地址。这不是广播或区块时间。是否为最终开盘的末笔，要看同哈希的开盘事件；节点没有推送的候选不会有接收记录。
- `snipe_pending_feed`：各路订阅、断线与重连的变化。`payload_timeout` 表示完整交易流停顿；`retryMs` 是计划等待时长，`pendingLastFullAtMs` 是该路最后一次收到完整交易的时间。
- `snipe_pending_gate`：父块进度、可见候选数、是尚未进入最后三批（`waiting_lots`）、候选未齐（`waiting_pending`）、候选 nonce 已被父块消耗（`stale_pending`），还是已经齐备并进入顺序模拟（`ready`）。齐备时保存有序 `pendingHashes`。`headMs`、`proofMs` 和 `planMs` 分别度量父块查询、项目/发送者核验与各钱包模拟。
- `snipe_pending_match`：同一开盘哈希是否先从待打包流收到；命中时保留原收包时间。`leadMs` 和节点健康都取首次收到开盘通知的时点，不用随后验证回执的时间或状态。
- `watch_started`：记录核验后的启动区块 `armBlock`。若建档后启动失败或被取消，报告只会有错误或停止事件，没有这条开盘监控启动记录。
- `snipe_send` / `snipe_ack`：准备提交和节点应答；应答不等于成交。`broadcastConcurrency` 是设置的并发上限，`broadcastRpcCount` 是应答时已投递的节点数。
- `snipe_race_outcome` / `snipe_receipt`：尝试序号、已知结果、回执区块和块内索引；若仍未知，不能算作成交。
- `snipe_first_buy`：延迟查询从开盘块至后续最多两块观察到的首买。比较「成交块 − 开盘块」，若同块再比较块内索引。停止太早或节点查询失败时可能缺少这条补充记录。
- `buy_skipped` 的 `failureKind: opening_price_cap`：价格保护拒绝。`openingNetOut`、`quotedNetOut` 和 `openingAmountOutMin` 分别为开盘净报价、当前净报价和开盘保护下限（代币最小单位）。

日志不保存钱包地址、RPC 凭据、会话、私钥或原始交易。公开交易哈希可在浏览器追溯链上交易发起者。
