# 预置首买：固定目标、链上守卫与限额竞争

## 与原 Pending 路径的区别

原路径需要先拿到可验证的末笔 Mint 候选，才能构建与发出买单；公共节点漏推末笔时，这个前提可能完全不成立。本路径先把目标、金额、开盘储备锚点、最低净到账和竞争上限预置到专用合约，再由本地服务按限额持续投递固定的 `execute(intentId)`。

开盘前的尝试不会买入。开盘后，只有池储备仍等于经过核验的初始锚点、税率在上限内、实际净到账满足固定底线，才允许成交。其他交易已经改变储备时放弃，不重新取上涨后的价格来降低底线。**不是广播成功就算买到，也不是 receipt.status=1 就算成交，只有匹配的 `Filled` 才是买入证据。**

这改变了“必须等末笔候选”的执行前提，但不是 Builder 排序承诺，不保证第一笔或一定成交。

## 当前版本边界

- BSC 主网 chain ID 56、固定 Corla catalog v4、原生 BNB、PancakeSwap V2 直连池。
- 一个 owner，也由该钱包作为唯一执行者；最多一笔 pending。**不是多钱包并行、不是同一 nonce 提价替换、不是无限制喷射或私有 Bundle。**
- 已核验失败回执一确认后，才允许下一笔固定意图交易。未知投递只查原哈希，不能盲目继续推进 nonce。
- 竞争按次数、Gas 最坏预算、区块、时间四个上限中最早到达的一个停止；120 次并不代表能持续竞争 300 秒。
- 正式价格准备需要项目还未开盘、只剩最后一份，并且能用公开可验证、仍有资格的假设 minter 完成只读末笔模拟。没有合格身份或节点不支持模拟时拒绝准备，不修改资格或协议 storage 来伪造成功。
- 不能将“事后知道真实末笔发送者的历史重放通过”当成“生产环境自动能找到该发送者”。白名单与 Agent 限制仍需真实模拟验证。

## 页面操作

进入「开盘狙击」，选择「预置首买 · 限额竞争」。切换模式只改变显示，不会迁移旧策略或自动启动。

1. 选择已导入的执行钱包、目标和预算。可先点「部署预览」并核对确认，**纯部署不依赖末笔模拟，不注入买入本金，不启动任务**。已登记的兼容执行器可以复用。
2. 只剩最后一份时点「准备与模拟 · 不发交易」，生成核验的储备锚点和最低净到账；页面不能编辑底线。
3. 「预置 / 授权预览」显示向执行器补入的本金、固定目标和参数，确认后才发送链上 `arm`。
4. 条件全部通过后点「核对并启动首买」，再确认本次限额竞争。部署、预置和启动是独立步骤，不会连带自动执行。
5. 停止按钮只停止新投递，不能撤回已经送入网络的交易。存在未决交易时保持钱包租约，直到核对结果。
6. 未买到的本金仍在执行器内。先「取消预置预览」并确认，待取消确认后，再「撤回闲置本金预览」并确认。收款人固定 owner，网页不能指定任意金额或任意收款人。

首次部署、预置、取消及撤回都另有 Gas，均需预览且仍受全局预算限制。失败竞争尝试同样消耗 Gas；本金没有被买入不等于完全没有费用。

## 实现与恢复

- 合约：`contracts/CorlaFirstBuyExecutor.sol`。固定协议身份与 Router；限定操作员、目标、时间、Gas 价格、尝试数，成功后锁定 Mint 与 Token，不能重复购买。内层买入失败被捕获，以保留外层次数消耗；没有任意外部调用接口。
- 准备：`src/firstbuy-prepare.mjs`。只读 `eth_simulateV1`，核验真实末笔假设、初始池证据、实际净到账、可卖出与执行路径。只允许假设发送者/接收者的原生余额覆盖，不改协议 code、storage、资格、nonce 或 Token 余额。
- 竞争：`src/firstbuy-runner.mjs`。固定 calldata 与计划，签后逐字段核对；签名哈希先落盘再交付网络；未决交易不能换新 hash；所有失败和未知尝试永久保守占用会话最坏 Gas 预算。
- 协调：`src/firstbuy-service.mjs`。单次预览 token 绑定配置版本、钱包清单和计划；与旧 Mint/狙击共用全局互斥、交易 journal 与钱包租约。canonical head 只缓存当前 `number + hash`，不是按高度盲缓存。
- 重启：`firstbuy.local.json` 保存公开的合约、owner 与未决计划元数据，不保存私钥或 raw 签名交易；签名前已持久化恢复标记。重启只读核对原交易，**不会自动恢复竞争、解锁、签名或广播**。

## 本地记录与验证

每次网页接受操作都会保存运行文件 `reports/snipe-runs/snipe-*.ndjson`。竞争事件包含固定意图、每笔投递哈希、ACK、可信回执区块哈希/索引、尝试数和保守费用；`bought=false` 与可信 `Filled` 分开记录，不保存钱包私钥、RPC 认证信息或原始签名。

```powershell
npm.cmd run compile:firstbuy
npm.cmd run test:firstbuy
npm.cmd test
```

编译只生成本地 artifact，不部署。合约测试在独立本机 Anvil EVM 运行；服务/runner/UI 测试不使用真实钱包或网络广播。

另有两条显式私有 fixture 的历史验证入口：

```powershell
node scripts/replay-firstbuy-simulate.mjs --help
node scripts/replay-firstbuy-fork.mjs --help
```

`simulate` 是实际节点历史 EVM 的自定义调用顺序；`fork` 写请求只准进入本机 Anvil。历史归档节点不可用时会保留失败报告，不改称成功。二者均不是完整区块、网络传播或真实 Builder 排名测试。

## 关于抢首笔

本地模拟能验证“若我的 execute 排在真实末笔之后、其他买单之前能否成交”与“别人先买时能否拒绝追高”，不能验证网络是否把交易排在那个位置。下一步需要依据主网运行记录量化每次投递、ACK、实际入块位置与竞争者位置，再评估专用低延迟节点、多执行钱包 lane 或真实支持的 Builder 通道。当前界面不会伪装存在尚未接入的贿赂费、防夹或私有排序功能。
